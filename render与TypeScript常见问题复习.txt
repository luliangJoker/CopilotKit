CopilotKit render 与 TypeScript 常见问题复习
整理日期：2026-11-06

这份笔记根据本次问答整理，重点区分实际运行的数据和 TypeScript 类型说明。
以下字段结构依据当前项目已安装的 SDK；更换版本时需要重新核对。

一、我们讨论的是哪行代码？

render: (props: VueToolCallRendererRenderProps<{ status: OrderFilter }>) =>
  h(OrderQueryResult, props),

先忽略类型说明，实际执行的部分是：

render: (props) => h(OrderQueryResult, props),

意思：CopilotKit 调用 render 时提供工具执行信息；我们用这些信息显示 OrderQueryResult 组件。

二、h() 是 TypeScript 新语法吗？

不是。h 是 Vue 提供的普通函数：

import { h } from 'vue'

基本写法：

h(标签或组件, 属性, 子内容)

例如：

h('p', null, '你好')

可以对应理解为模板中的：

<p>你好</p>

显示组件时：

h(OrderQueryResult, { status: currentStatus })

可以对应理解为：

<OrderQueryResult :status="currentStatus" />

OrderQueryResult 是组件，h 是函数。
h 创建组件的虚拟节点描述，由 Vue 负责渲染；调用 h 不代表直接删除或查询订单。

三、props 这个对象是谁创建的？

CopilotKit 内部代码根据本次工具调用创建并提供给 render。
不是我们手动创建，也不是 OrderQueryResult 组件决定外层结构。

可以类比点击事件：Vue 把 event 交给点击处理函数；这里是 CopilotKit 把工具执行信息交给 render。

render: (props) => h(OrderQueryResult, props)

这条路径是：
CopilotKit 提供信息 → render 的 props 接收 → h 将信息传给 OrderQueryResult。

props 是我们给函数参数取的变量名，可以改名，但使用位置要一起修改。
OrderQueryResult 内部的 defineProps 用于声明组件要接收的参数。

四、普通工具的 render 参数只有三个字段吗？

不是。当前 VueToolCallRendererRenderProps 定义了五个外层字段：

name：工具名称。
toolCallId：本次工具调用的编号。
args：这次调用实际提供的工具参数。
status：工具执行阶段。
result：工具返回结果。

执行中可以举例为：

{
  name: 'filter_orders',
  toolCallId: 'call_001',
  args: { status: '待付款' },
  status: 'executing',
  result: undefined,
}

完成后可以举例为：

{
  name: 'filter_orders',
  toolCallId: 'call_001',
  args: { status: '待付款' },
  status: 'complete',
  result: '{"applied":true,"status":"待付款","count":1}',
}

call_001 和数量都是示例值，不是固定值或需要手动填写的内容。
result 在执行中按当前 SDK 定义是 undefined，不是 null。
正常完成时，本例 handler 返回的对象被转换为结果字符串。

五、两个 status 为什么不一样？

props.args.status：订单筛选条件，例如“待付款”。
props.status：工具执行阶段，例如 executing、complete，由 CopilotKit 管理。

它们名字相同，但位置和含义不同。
本项目的准备阶段对应 ToolCallStatus.InProgress，当前值为 inProgress；不要误写成 in-progress。

六、parameters 是什么？args 是不是 parameters 的值？

代码：

parameters: z.object({
  status: z.enum(['全部', '待付款', '待发货', '已完成']),
})

parameters 的值是 Zod 创建的规则对象。
它描述：工具需要一个对象，其中 status 只能选择这四种字符串。

args 是这次实际调用的参数，例如：

{ status: '待付款' }

准确关系：
parameters 描述规则 → AI 参考规则提供调用参数 → CopilotKit 将实际参数放入 render 的 args。

不要说“args 就是 parameters 的值”，这会把规则对象和实际调用参数混为一谈。

七、parameters 写了规则，实际数据就一定正确吗？

不是。
规则供模型了解工具参数，并帮助 TypeScript 推导类型。
当前 useFrontendTool 示例没有额外调用 Zod parse 对运行时参数进行校验。
因此不能把“声明了规则”理解为“实际数据一定已经通过检查”。

八、这一长段类型说明怎么拆？

props: VueToolCallRendererRenderProps<{ status: OrderFilter }>

props：函数参数的变量名。
冒号：开始说明这个参数的 TypeScript 类型。
VueToolCallRendererRenderProps：CopilotKit 提供的普通工具显示参数类型。
<{ status: OrderFilter }>：补充说明本工具的 args 格式。

本项目的 OrderFilter 表示：

'全部' | '待付款' | '待发货' | '已完成'

竖线表示“或者”，即可以是其中一种。

九、为什么尖括号约束的是 args.status？

因为 CopilotKit 定义类型时，把传入的类型用在 args 字段上。
下面只是用于理解的简化定义，不是 SDK 完整源码：

type VueToolCallRendererRenderProps<T> = {
  name: string
  toolCallId: string
  args: T
  status: string
  result: string | undefined
}

关键是 args: T。
我们把 T 填成 { status: OrderFilter } 后，相当于：

args: { status: OrderFilter }

这叫 TypeScript 泛型：定义时留一个类型位置，使用时填入具体类型。
尖括号不是函数调用，也不是传入实际数据。

十、parameters 已经写了，为什么还补 TypeScript 类型？

理想情况下，TypeScript 能从 parameters 推导 render 参数类型，就不用重复声明。
但当前项目的 SDK render 类型包含不同的写法，TypeScript 没有成功自动推导这个回调参数。
本项目省略说明时，曾实际报错：参数 props 隐式具有 any 类型。

所以显式类型是在补充编译器没推导出来的信息，不是再次检查实际参数。
不能把当前项目的推导问题说成所有 SDK 版本和所有写法都存在的问题。

十一、不写类型，props 的实际值会变吗？

不会。CopilotKit 仍然传入同样的工具执行信息。

带类型：

render: (props: VueToolCallRendererRenderProps<{ status: OrderFilter }>) =>
  h(OrderQueryResult, props),

省略类型：

render: (props) => h(OrderQueryResult, props),

实际运行的数据来源和结构不因类型说明而改变。
TypeScript 类型说明会在转换为 JavaScript 时被去掉。
它不会创建、过滤、转换或校验实际 props。

十二、到底能不能省略？会不会报错？

当前项目：
不能直接省略后仍指望类型检查通过，会出现隐式 any 错误。
当前 build 命令包含 vue-tsc 类型检查，因此也会失败。

允许隐式 any 的宽松配置：
这段回调可能可以省略类型，不会仅因为省略类型就在运行时出错。
但其他代码和配置仍可能产生别的错误，不能因此保证整个项目必然正常。

没有为了简化教学而修改当前项目的 TypeScript 配置。
当前项目保留显式类型即可，不需要背长类型名。

十三、另一种 render 参数类型有什么区别？

VueToolCallRendererRenderProps：配合 useFrontendTool，展示工具执行过程和结果。
VueHumanInTheLoopRenderProps：配合 useHumanInTheLoop，等待用户确认或选择。

后者在等待用户回答的执行阶段额外提供 respond 方法。
respond 将处理结果交回 AI，结束等待；它本身不负责删除订单。

十四、这一轮最重要的区别

parameters：工具参数规则。
args：本次调用的实际参数。
render 的 props：CopilotKit 提供的整份工具执行信息，其中包含 args。
VueToolCallRendererRenderProps<...>：给 TypeScript 的类型说明。
h(OrderQueryResult, props)：显示组件并传入工具信息。

后续教学注意：
- 先说明代码实际运行做什么，再讲类型。
- 举例省略字段时明确标注，要求完整结构时列出当前 SDK 规定的全部字段。
- 区分规则对象、实际数据、类型说明，不互相替代。
- 不把类型检查与运行时校验混为一谈。
- 类型是否可以省略，以当前项目实际类型检查结果为准。
- 学习者需要掌握数据流，不需要背诵长类型名称。
